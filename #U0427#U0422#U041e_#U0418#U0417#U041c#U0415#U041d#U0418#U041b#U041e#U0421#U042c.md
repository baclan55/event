# Синхронизация ролей Discord → сайт — что добавлено

## Файлы

- **`bot/roleSync.ts`** (новый) — логика синка: карта Discord role ID →
  роль на сайте, обновление `user_roles`/`user_role_history`/`users.role_id`
  с сохранением вручную выданных ролей (Technical Administrator).
- **`bot/eventAttendanceBot.ts`** (изменён) — подключает `roleSync.ts` и
  запускает периодический синк в обоих режимах бота (прямое подключение и
  relay через Cloudflare Worker), плюс опциональный мгновенный синк по
  `guildMemberUpdate`.
- **`docker-compose.yml`** (изменён) — новые переменные окружения у
  сервиса `event-bot`: `DISCORD_GUILD_ID`, `DISCORD_ROLE_SYNC_INTERVAL_MS`,
  `DISCORD_ROLE_SYNC_LIVE`.
- **`.env.example`** (изменён) — те же переменные для справки.
- **`README.md`** (изменён) — новый раздел «Синхронизация ролей Discord →
  сайт» с полным описанием и инструкцией по настройке.

Просто скопируйте эти файлы в соответствующие места в вашем проекте
(заменив существующие) и задеплойте как обычно.

## Что нужно сделать на вашей стороне

1. Скопируйте файлы поверх текущих в репозитории.
2. Узнайте ID вашего Discord-сервера (Настройки → Расширенные → Режим
   разработчика → ПКМ по иконке сервера → «Скопировать ID сервера»).
3. Задайте `DISCORD_GUILD_ID=<этот ID>` в `.env` рядом с
   `docker-compose.yml` (или в Portainer у стека).
4. Пересоберите и перезапустите только сервис `event-bot`:
   ```
   docker compose up -d --build event-bot
   ```
5. Проверьте логи — должно появиться `[role-sync] Проверено сотрудников:
   N, обновлено: M.` при каждом проходе (по умолчанию — раз в 5 минут).

Больше ничего менять не нужно — права бота (permissions) трогать не
пришлось, токен и приглашение остаются прежними.

## Коротко про права бота (ваш вопрос)

- **Периодический синк (по умолчанию, `DISCORD_ROLE_SYNC_LIVE=0`)** —
  никаких новых прав/intent-ов не требует. Бот и так состоит на сервере
  и читает канал со сборами; запрос «получить участника сервера» — это
  обычный REST-запрос, доступный любому боту-участнику сервера без
  привилегированного intent GUILD_MEMBERS. Ничего в Developer Portal
  включать не нужно, переприглашать бота — тоже.
- **Мгновенный синк (`DISCORD_ROLE_SYNC_LIVE=1`)** — единственное, что
  требует доп. настройки: включить переключатель **Server Members
  Intent** в Discord Developer Portal → ваше приложение → **Bot** →
  **Privileged Gateway Intents**. Это настройка на уровне приложения
  бота, а не прав в ссылке-приглашении, поэтому **переприглашать бота на
  сервер не нужно** — достаточно включить переключатель и перезапустить
  процесс бота (`docker compose restart event-bot`).
  ⚠️ В вашем случае бот, скорее всего, работает через
  `DISCORD_RELAY_URL` (relay режим — это видно по умолчанию в
  `docker-compose.yml`, так сделано потому что с большинства VDS в РФ
  Discord Gateway недоступен напрямую). В этом режиме нет постоянного
  WebSocket-соединения, поэтому мгновенный синк там не работает — будет
  действовать только периодический (раз в
  `DISCORD_ROLE_SYNC_INTERVAL_MS`, по умолчанию 5 минут), и этого более
  чем достаточно для такой задачи.

## Логика синка коротко

- Раз в 5 минут (настраивается) бот проходит всех сотрудников с
  привязанным Discord ID, запрашивает их текущие роли на сервере и
  сравнивает со списком из задания.
- Роль появилась на Discord → появляется на сайте. Роль сняли (или
  человек вышел с сервера) → снимается на сайте.
- Если у сотрудника несколько ролей из списка одновременно — на сайте
  выставятся все (сайт это уже поддерживает).
- Technical Administrator синк никогда не трогает — ни не добавляет, ни
  не снимает, что бы ни происходило на Discord.
- Сотрудников, которых ещё нет в «Составе» (нет привязанного Discord ID),
  синк не создаёт — только обновляет тех, кто уже зарегистрирован на
  сайте (через вход или через одобренную заявку).
